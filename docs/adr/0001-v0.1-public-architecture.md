# ADR 0001: v0.1 public architecture

- Status: Accepted
- Date: 2026-08-26
- Decision owners: libfmp maintainers
- Scope: Issues #1 through #10, with implementation beginning in #2

## Context

The first release is a deliberately small walking skeleton whose purpose is to
claim and validate the public Rust and Python names before broad endpoint
coverage begins. `artifacts/documentations/outer.md` is the sole source of truth
for FMP endpoints, query parameters, authentication, and response shapes.
`libitofin` is an architecture and packaging reference only.

The design must keep the Rust core independent of Python, preserve FMP's wire
semantics, and allow direct FMP access as well as custom routers and proxies
without changing endpoint code.

## Decision

### Package and workspace names

The repository will become a virtual Cargo workspace using resolver 3, with
explicit members:

- `crates/libfmp`: Cargo package and Rust library `libfmp`.
- `crates/fmp-py`: Cargo package `fmp-py`, built as a `cdylib`, depending on
  `libfmp`.

The workspace owns the shared version, edition, repository, and other common
package metadata. Once a license is selected, its shared metadata will also be
centralized there. The core crate has no PyO3 dependency. The binding crate
contains only Python facades, conversions, runtime integration, and error
translation.

This ADR does not select a license. License selection and consistent Cargo,
Python, and repository metadata are deferred to #9 and are a publication
blocker for both packages.

The published names are:

- crates.io package and Rust library: `libfmp`
- binding Cargo package: `fmp-py`
- PyPI distribution: `fmp-py-sdk`
- Python import package: `fmp_py`
- private native extension: `fmp_py._native`

No hyphenated Python import is supported or documented.

### Python package layout

The binding uses a binding-local mixed Python/Rust package, following the
`libitofin` layout:

```text
crates/fmp-py/
├── Cargo.toml
├── pyproject.toml
├── src/
│   └── lib.rs
└── python/
    └── fmp_py/
        ├── __init__.py
        ├── __init__.pyi
        ├── quote.py
        ├── quote.pyi
        └── py.typed
```

Maturin is configured with `python-source = "python"` and
`module-name = "fmp_py._native"`. The PyO3 module is named `_native`.
`fmp_py.__init__` explicitly exports the supported facade and exception names;
the native extension remains an implementation detail.

The stable v0.1 import is:

```python
from fmp_py import FmpClient, FmpError
```

The quote-short result is a `list[fmp_py.quote.QuoteShort]`. Python accepts
ordinary strings for identifiers and converts them to validated Rust types at
the boundary. It does not expose Rust lifetimes, generics, transport traits, or
runtime objects.

### Client names and execution posture

The Rust client is `libfmp::Client`, constructed through
`libfmp::ClientBuilder`. Rust HTTP methods are async-native. The first frozen
endpoint method is conceptually:

```rust,ignore
async fn quote_short(&self, ticker: &Ticker) -> Result<Vec<QuoteShort>>;
```

No synchronous Rust client is promised in v0.1.

Python exposes a synchronous `fmp_py.FmpClient`. Its methods delegate to the
async Rust core through a runtime owned by the binding and release the GIL while
waiting. A Python async facade is explicitly deferred and may later be added
under a distinct name such as `AsyncFmpClient`.

### Public Rust organization and layering

Implementation proceeds bottom-up:

1. fundamental wire units and codecs;
2. endpoint query/request descriptions;
3. typed response models;
4. the shared client and transport;
5. thin Python facades.

The public Rust modules are:

- `types`: identifiers, dates and timestamps, pagination, ranges, and numeric
  wire units;
- `endpoints`: domain-grouped query/request types, initially `endpoints::quote`;
- `responses`: domain-grouped response models, initially
  `responses::quote::{Quote, QuoteShort}`;
- `client`, `config`, and `error`.

The crate root re-exports `Client`, `ClientBuilder`, `Error`, and `Result`.
Endpoint code describes only the HTTP method, relative path, typed query, and
response shape. Base URLs, authentication, headers, redirects, timeouts, and
HTTP execution remain transport concerns.

### Fundamental wire types

`Ticker`, `Cik`, `Cusip`, and `Isin` are opaque, non-empty string newtypes with
private storage. In v0.1 they reject empty, whitespace-only, and control-bearing
values but do not impose undocumented character sets, fixed lengths, digit-only
rules, normalization, or padding. They preserve the supplied representation,
including leading zeroes. `Ticker` accepts documented international and index
forms such as `000001.SZ` and `^VIX`, while rejecting commas so it cannot break
list encoding.

`TickerList` owns a non-empty list of `Ticker` values. Its query codec, rather
than `Ticker`, is responsible for comma encoding.

Exchange, currency, and country codes are open string newtypes, not closed
enums, because the provider's supported values can grow. Documented provider
sentinels such as an empty string or `"N/A"` are converted to `None` only on
fields whose `outer.md` examples establish that behavior; sentinels are not
valid identifiers.

The public API also provides:

- a date-only `Date` newtype;
- a timezone-less `ApiDateTime` newtype for values such as
  `YYYY-MM-DD HH:MM:SS`, without inventing a timezone;
- distinct `UnixSeconds(i64)` and `UnixMilliseconds(i64)` newtypes;
- `Page(u32)`, an integer `Limit` newtype, and an inclusive `DateRange` that
  rejects a start later than its end; limit validation applies only documented
  endpoint-specific bounds and does not invent a global non-zero rule;
- `f64` wire aliases for prices, changes, percentages, and market values;
- `u64` wire aliases for volumes and counts.

The chosen date implementation remains hidden behind the public date types.
Response-field optionality follows the documented wire examples rather than
being inferred for convenience. Serde mappings use Rust snake_case names with
exact explicit or camelCase wire renames.

### Bare-array response semantics

A documented bare JSON array remains a collection throughout the public API:

- Rust returns `Vec<T>`.
- Python returns `list[T]`.
- An empty successful response remains an empty collection.
- Multiple rows remain representable and retain their order.

The client does not silently select the first row, translate an empty array to
not-found, or expose a singular `Option<T>` for an array response. Singular
convenience helpers are outside v0.1.

### Proxy and router boundary

The transport will support a configurable base URL and path prefix, direct FMP
API-key authorization, bearer or custom authorization, custom secret query
parameters, arbitrary default headers, and no-auth local/mock use. These choices
belong exclusively to client configuration and transport. Endpoint modules must
remain unchanged when switching between direct FMP access and a proxy.

Secret values are redacted and protected from accidental header replacement,
error rendering, logging, and cross-origin redirect forwarding.

## v0.1 scope

Included:

- workspace and package scaffolding;
- fundamental types and wire codecs;
- proxy-ready transport and stable error boundary;
- reusable endpoint/query machinery;
- the `GET /stable/quote-short?symbol=...` Rust vertical slice;
- the synchronous Python facade, typing, packaging, and release validation.

Excluded:

- full quote and batch quote endpoints;
- retries, caching, streaming, and pagination execution;
- a synchronous Rust client or asynchronous Python client;
- singular-result convenience helpers;
- all endpoint families other than quote-short.

## Implementation order

The dependency order is:

`#1 -> #2 -> #3 -> #5 -> #4 -> #6 -> #7 -> #8 -> #9 -> #10`

A circular dependency between issues #4 and #5 was discovered during the
architecture review. GitHub issue #5 has now been corrected to depend on #2 and
#3 and to establish the base error/configuration contract. Issue #4 depends on
#5 and owns mock HTTP, non-2xx, redirect, and transport-error integration
checks. No implementation should follow the superseded circular form.

## Acceptance checks

- `cargo metadata` reports exactly the core and binding workspace packages.
- `cargo tree -p libfmp` contains no PyO3 dependency.
- Core tests require neither a network connection nor a real credential.
- Fixtures cover leading-zero identifiers, permissive documented ticker forms,
  exact camelCase/special wire names, date and timezone-less datetime parsing,
  and seconds-versus-milliseconds separation.
- The quote-short fixture decodes documented one-row, empty, and multi-row bare
  arrays without changing their shape.
- `maturin build` produces distribution metadata named `fmp-py-sdk` and a clean
  environment imports `FmpClient` from `fmp_py`.
- Rust and Python artifacts report the same version.
- Issue #9 selects a license and applies matching Cargo, Python, and repository
  metadata before either package is published.
- Direct FMP and custom proxy configurations exercise the same endpoint code
  against deterministic mock transports.
- Debug output, errors, snapshots, and logs contain no API keys, tokens, custom
  secret values, or authenticated URLs.

## Repository guardrails

Workflow files being laid out by the user are user-owned. Implementation must
preserve and avoid overwriting unrelated changes in `.github/`, `scripts/`,
`.releaserc.json`, `.worktrees/`, and any other dirty paths.

Every commit must be created through the `git ch` alias. Direct `git commit` is
prohibited.

## Consequences and risks

- The private `_native` extension permits Python-level compatibility shims and
  future facade evolution without renaming the distribution or import package.
- Async Rust plus synchronous Python keeps one core transport, but the binding
  must manage runtime lifecycle carefully and document that synchronous calls
  block the calling Python thread while the GIL is released.
- Permissive opaque identifiers favor wire fidelity over standards validation;
  stronger validation can be additive only if it does not reject documented or
  provider-returned values.
- Numeric aliases preserve straightforward serialization but deliberately do
  not provide decimal financial arithmetic; such convenience belongs above the
  wire-model layer.
- Registry availability is not a reservation and must be checked again
  immediately before publishing.
