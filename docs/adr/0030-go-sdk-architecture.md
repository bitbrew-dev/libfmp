# ADR 0030: Go SDK architecture

- Status: Proposed
- Date: 2026-09-21
- Decision owners: libfmp maintainers
- Scope: `sdk/go`, the generator crate, release plumbing for the Go module

## Context

libfmp is a Rust-first SDK for the FMP HTTP API. Its value is the endpoint
contract: 30 registry domains, 271 client methods, 83 query types, 130
response models, the shared codec policy (ADR 0002), advisory endpoint
metadata, and 292 recorded wire fixtures under `crates/libfmp/tests/fixtures`.
The crate performs no computation of its own: every call is one HTTPS GET,
one JSON decode, and one structured error path.

`sdk/go` holds a placeholder README from PR #249 and nothing else. The
sibling project `libitofin` ships a Go SDK at the same path as a cgo binding
over a C ABI crate (`libitofin-ffi`, cbindgen header, `sdk/go/vX.Y.Z` tags,
native packages attached to each release). That design is right for a
QuantLib port, where the numerical core cannot be re-implemented cheaply.

The question for libfmp is whether anything crosses the Go boundary that Go
cannot recompute cheaply. The answer is no: the JSON payload must be decoded
into Go values regardless of where the HTTP request is issued, and every rule
that makes libfmp trustworthy (paths, query encoding, codec policy, redaction,
never-retry, body caps) is data or a small amount of code, not a numerical
kernel.

## Decision

### Integration approach: pure Go, no cgo

The Go SDK is a pure Go module that speaks HTTP directly. It reuses the Rust
crate as the **contract source**, not as a linked library:

- Endpoint identity, paths, argument kinds, and method names come from the
  registry under `crates/fmp-py-gen/registry` (the same 271 verified entries
  `registry_check` gates today).
- Response models are generated from the Rust `responses` modules by the same
  `syn` parser that drives the Python model generator.
- Wire fixtures are shared: Go parity tests read
  `../../crates/libfmp/tests/fixtures` relative to the module, so the Rust and
  Go decoders are proven against identical bytes and fixtures never drift.

Consequences that follow from this choice:

- `go get` works with `CGO_ENABLED=0`, cross-compiles, and needs no native
  package, header, or loader path.
- The Go SDK can never be ahead of the Rust contract: a generator gate fails
  when Go and the registry disagree.
- Divergence risk moves into the generator and the codec layer, which is why
  both get parity gates (below).

### Module identity and layout

Mirrors the sibling's conventions so both SDKs feel the same to a consumer:

| Item | Value |
| --- | --- |
| Module path | `github.com/bitbrew-dev/libfmp/sdk/go` |
| Package name | `fmp` (consumers alias the import, as the sibling's `itofin` does) |
| Go version | `go 1.27.1` in `go.mod`, enforced by the check script |
| Layout | flat package at `sdk/go`, `examples/<name>/main.go`, no `internal/` until needed |
| Generated files | one `<domain>_models.go` and one `<domain>.go` per registry domain, plus `queries.go` (the query types more than one domain uses, so each Rust query type has one Go type) and `namespaces.go` (the `Namespaces` struct `Client` embeds, one field per generated domain), all headed `// Code generated by fmp-py-gen gen_go. DO NOT EDIT.` |
| Hand-written files | `client.go`, `auth.go`, `errors.go`, `codecs.go`, `transport.go`, `version.go` |

The module path ends in `go`, so every consumer writes
`fmp "github.com/bitbrew-dev/libfmp/sdk/go"`. That is the sibling's shape and
the cost is one alias per import; it is accepted for consistency.

### Client surface

`fmp.NewClient(opts ...Option) (*Client, error)` mirrors `ClientBuilder`
one-for-one. Every option name is the Rust builder method in Go casing:

| Rust builder | Go option | Notes |
| --- | --- | --- |
| `base_url` | `WithBaseURL` | same URL validation and unsafe-URL refusal |
| `path_prefix` | `WithPathPrefix` | |
| `authentication` | `WithAuthentication(Authentication)` | constructors `FmpHeader`, `FmpQuery`, `Bearer`, `CustomHeader`, `CustomQuery`, `FmpHeaderFromEnv` (`FMP_API_KEY`) |
| `default_header` | `WithDefaultHeader` | same protected-field collision rule |
| `user_agent` | `WithUserAgent` | |
| `timeout` | `WithTimeout` | one logical deadline across redirects and body read |
| `connect_timeout` | `WithConnectTimeout` | |
| `max_response_body_bytes` | `WithMaxResponseBodyBytes` | `io.LimitReader` plus one extra byte to detect overflow |
| `danger_allow_insecure_authentication` | `WithDangerAllowInsecureAuthentication` | default refuses credentials over plain HTTP |
| `redirect_policy` | `WithRedirectPolicy` | `RedirectNone`, `RedirectSameOrigin` (default) |
| `executor` | `WithHTTPClient(*http.Client)` | the seam for tests and proxies |

Every endpoint method takes a `context.Context` first, then the typed query,
and returns `([]Model, error)` for bare-array endpoints. Method names are the
registry `method` values in Go exported casing, grouped by domain the way the
Python facade groups namespaces (`client.Quote.Full(ctx, q)` is the target
shape; the walking skeleton settles it).

### Errors and secrets

`*fmp.Error` carries the Rust categories verbatim: `Category`
(`Validation`, `Configuration`, `Transport`, `Status`, `Decode`), `Message`,
`Endpoint` (logical id, never a URL), `Status`, `Body` (a `SafeBody`: capped,
redacted), and `ConfigurationKind`. Rules carried over:

- Go's `*url.Error` embeds the full request URL, including `apikey=` for the
  query-authentication mode. The client wraps every transport error before it
  escapes and never formats a URL that can contain a credential.
- No retries, ever. 401, 402, 403, 429, 500, and 503 all surface as one
  `Status` error with a redacted body after exactly one request, matching the
  status-family test in `crates/libfmp/tests/endpoints.rs`.
- Environment names match the Rust live opt-in tests: `FMP_API_KEY`,
  `FMP_LIVE_TESTS`, `FMP_PROXY_BASE_URL`, `FMP_PROXY_TOKEN`,
  `FMP_PROXY_PATH_PREFIX`, `FMP_TENANT`. Live tests are skipped unless
  `FMP_LIVE_TESTS=1`.

### Codec policy (Rust to Go type table)

Go 1.27 ships `encoding/json/v2` as stable; the SDK uses it, with
`encoding/json/jsontext` for raw values. The mapping keeps ADR 0002's rule
that no wire information is invented or lost:

| Rust | Go | Rule |
| --- | --- | --- |
| `String` newtypes (`Ticker`, `ExchangeCode`, ...) | `string` | validated on the query side only |
| `Price`, `Change`, `Percentage`, `MarketValue` (`f64`) | `float64` | |
| `Volume`, `Count`, `MarketCapitalization` (`u64`) | `uint64` | |
| `StatementAmount` (`i64`) | `int64` | |
| `Option<T>` | `*T` | `nil` for absent and for JSON `null` |
| `NumericString`, `PercentString` | `string` | exact wire text, never scaled |
| `NumberOrNumericString`, `PercentageValue` | `fmp.NumberOrString` | holds `jsontext.Value`; accessors report which form arrived |
| `Date` (`YYYY-MM-DD`) | `fmp.Date` | civil date, no zone, own type |
| `UsDate` (`MM-DD-YYYY`) | `fmp.UsDate` | same civil date, US wire text; `.Date()` converts |
| `ApiDateTime` (naive) | `fmp.DateTime` | naive, own type; not `time.Time` |
| `IsoTimestamp` | `string` | exact RFC 3339 text, offset and precision preserved |
| `DateOrDateTime`, `OpaqueDateText` | `string` | which form arrived is preserved |
| `UnixSeconds`, `UnixMilliseconds` | `fmp.UnixSeconds`, `fmp.UnixMilliseconds` (`int64`) | `.Time()` helpers |
| `WireBool` | `bool` | validated string flags stay `string` |
| `DynamicJson`, `DynamicObject` | `jsontext.Value` | lossless raw bytes; no float64 round trip |
| `serde_json::Number` (`Number`, `Option<Number>`) | `jsontext.Value` | raw digits kept, integer and decimal spellings preserved; a present value must be a JSON number |
| `BinaryPayload` | `fmp.BinaryPayload{Data, ContentType, ContentDisposition}` | |
| `SecretUrl` (`FinancialReportDate.link_json`, `link_xlsx`) | `string` | exact wire text; the SDK never formats a decoded row into an error, log, or body, so the only way the URL reaches output is a caller printing it, which is explicit (the Python binding exposes the same `str`) |
| `#[serde(flatten)] DynamicObject`, or the single `DynamicObject` of a struct with a hand-written `Deserialize` (`FinancialReportJson.sections`) | `jsontext.Value` with struct tag `json:",embed"` | every member no named field claims, collected and re-emitted in place; a duplicate of a named member fails re-encoding, as the Rust serializer rejects reserved keys |
| `#[serde(rename = "1D")]` | struct tag `json:"1D"` | |

Required-field fidelity is kept. serde rejects a missing non-optional field
while `encoding/json` zero-fills silently, so the generator emits a shadow
struct with pointer fields for every required member and an `UnmarshalJSON`
that reports a `Decode` error naming the first missing field. Unknown members
are ignored, as in Rust (no `deny_unknown_fields` exists in the crate).

Four field codecs need more than a pointer, because json/v2 sets a pointer
to nil for both a missing key and a JSON null. Their shadow member is the raw
`jsontext.Value` (empty means missing) and the generated decoder finishes the
job: `deserialize_with = "required_option"` (key required, null allowed,
public field `*T`), `with = "empty_date"` and `with = "empty_or_null_date"`
(`""` is absent, null rejected or absent respectively, public field
`*fmp.Date`; the marshal side never re-emits `""` since the SDK is read-only),
`DynamicObject` (the value must be a JSON object), and the embedded rest
member (`json:",embed"`, never required, normalised to `{}` when no member is
left over). The discovery reader flags a struct whose file carries a
hand-written `impl Deserialize`; the generator accepts exactly one shape for
it, plain members plus one `DynamicObject` holding the rest, and fails naming
the struct otherwise. `FiscalYear` has no Go codec on purpose: no public model
uses it, and the generator fails if one appears rather than widening it to
`NumberOrString`.

### Generator placement

`crates/fmp-py-gen` gains a `gen_go` binary. The `syn` parser and model IR
now living under `src/bin/gen_models` are promoted into the crate library so
both emitters share one reader; `registry_check` keeps printing
`registry ok: 271 verified, 0 trusted`. The crate name is now a misnomer and
a rename to `fmp-gen` is deferred to its own change so this ADR stays small.
Generated Go must be byte-identical on re-run (`git status` clean after
`cargo run -p fmp-py-gen --bin gen_go`), exactly like the Python models.

`gen_go --domain <name>` generates named domains; with no argument it
regenerates every domain whose `<domain>.go` carries the generated header,
and `--all` regenerates all 30. The two shared files are always rewritten
from the union of generated domains, so they change whenever a domain is
added: after merging parallel domain branches, run `gen_go` once more and
commit the result. A domain whose response models live in another domain's
file (`forex` returns `quote::Quote`) requires that domain to be generated
first, and the generator says so. Query argument kinds are encoded by
`<kind>Param` helpers in the hand-written `query.go`; a kind without a helper
fails the generator naming the helper to add.

### Verification gates

| Gate | Where |
| --- | --- |
| `gofmt`, `go vet`, `golangci-lint` v2 (small explicit set), `go test -race -count=1` | `scripts/check_go_sdk.sh`, run by a `files:`-scoped pre-commit hook and a `go-sdk.yml` workflow |
| Fixture parity: every fixture decodes in Go without error and re-encodes to the same field set | `sdk/go/*_parity_test.go`, generated per domain |
| Coverage audit: every registry method has a Go method | `scripts/check_go_coverage.py --strict`, mirrors the sibling's audit |
| Generator idempotency | byte-identical regeneration |
| Examples compile and run offline | `go run ./examples/...` against `httptest.Server` |

The pre-commit hook is scoped by `files:` so Rust-only commits do not pay for
Go checks, mirroring the sibling's `go-bindings-tests` hook.

### Versioning and tags

- Go modules require `v`-prefixed tags, and a subdirectory module needs the
  directory prefix: `sdk/go/vX.Y.Z`. libfmp's core tag format is `X.Y.Z`
  (no `v`); the two coexist because the Go tag carries its own prefix.
- The Go module shares the workspace version. The release workflow creates
  `sdk/go/vX.Y.Z` at the release commit after the crates.io and PyPI jobs, the
  way the sibling's release does. Releases stay user-triggered.
- No Go tag is pushed until the walking skeleton has settled the public
  names: once the module proxy has fetched a version it is immutable.
- Consequence to accept: a `feat(sdk/go)` commit minor-bumps the shared
  version and republishes libfmp and fmp-py with no Rust change.

## Alternatives considered

- **cgo over a `libfmp-ffi` crate (the sibling's design).** Rejected for
  this crate: the JSON still has to be decoded in Go, so the bridge adds a
  native package per platform, a C compiler and cgo requirement, loader-path
  setup, and a second ABI surface, and buys nothing the registry does not
  already provide. It remains the right call for `libitofin`.
- **uniffi.** Go support is a community generator
  (`NordSecurity/uniffi-bindgen-go`, major version 0, tied to specific
  uniffi releases) and still requires cgo. Rejected for the same reasons.
- **Hand-written Go without a generator.** Rejected: 271 methods and 130
  models drift immediately; the Python binding's registry-driven generation
  is the proven pattern.
- **Package at `sdk/go/fmp` to avoid the `go` path element.** Rejected for
  consistency with the sibling; the alias cost is one line per import.

## Phase plan

| Phase | Scope | Exit check |
| --- | --- | --- |
| 0 walking skeleton | `go.mod`, `client.go`, `auth.go`, `errors.go`, redaction, hand-written `quote` full and short plus one no-query endpoint, first parity test, one example, `check_go_sdk.sh`, hook, workflow, README | `go test -race` green; names reviewed; no tag |
| 1 codecs | `fmp.Date`, `fmp.DateTime`, Unix types, `NumberOrString`, dynamic values, `BinaryPayload`, table tests mirroring `codecs.rs` | parity with Rust codec tests |
| 2 generator | promote parser to lib, `gen_go` emitting models plus methods plus shadow-struct decode for the quote domain, idempotency gate, coverage audit script | quote domain regenerates byte-identical; hand-written quote deleted |
| 3 fan-out | one worker per remaining domain (29), generated code plus parity tests against every fixture | 271 methods, `check_go_coverage.py --strict` green |
| 4 release plumbing | `sdk/go/vX.Y.Z` tag job in `semantic-release.yml`, `docs/endpoint-coverage.md` Go column, README install section | dry-run reviewed by the user; first tag is user-triggered |

## Acceptance checks

- `go vet ./...`, `golangci-lint run`, and `go test -race -count=1 ./...`
  pass from `sdk/go` with `CGO_ENABLED=0`.
- Every fixture under `crates/libfmp/tests/fixtures` decodes through the Go
  model the registry maps it to.
- `scripts/check_go_coverage.py --strict` reports 271 of 271.
- No test, example, or error message can print a credential.
- `cargo run -p fmp-py-gen --bin registry_check` still ends with
  `registry ok: 271 verified, 0 trusted`.

## Consequences and risks

- Two decoders now implement one contract. The shared fixtures and the
  generator are the only defence; both are gated.
- `encoding/json/v2` is new in 1.27. The opt-out `GOEXPERIMENT=nojsonv2` is
  slated for removal, so the SDK does not rely on v1 semantics anywhere.
- The Go module has no endpoint-metadata surface at first, like the Python
  binding. Generated descriptors carry the endpoint id and path; advisory
  metadata (delay, geography, add-on) is a follow-up.
