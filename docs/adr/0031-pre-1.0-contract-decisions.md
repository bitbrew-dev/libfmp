# ADR 0031: Pre-1.0 contract decisions

- Status: Accepted
- Date: 2026-09-24
- Decision owners: libfmp maintainers
- Scope: the 0.12 hardening pass (#339 to #349), all three SDKs

## Context

The 0.12 hardening pass is the last chance to change public shapes before
1.0. Several review findings asked "should this change?" and the maintainer
answered each one. This ADR records those answers in one place so later
changes do not reopen them. The implementing issues are listed per decision;
this ADR does not claim they have landed.

The semver rules that follow from these decisions live in
[Status and support](../../wiki/status.md#stability-and-semver).

## Decisions

### Rust `Error` keeps `PartialEq`/`Eq` and never gets a source chain

| Aspect | Decision |
| --- | --- |
| Derives | `Error` keeps `PartialEq` and `Eq` |
| `std::error::Error::source` | always `None`; no wrapped `reqwest`, `url`, or `serde_json` error |
| Why | an inner transport or URL error can print the request URL, which carries `apikey=` in the query authentication mode; flattening the cause into a redacted message is the only way to keep secrets out of every `Display` and `Debug` chain |
| Cost accepted | callers cannot downcast to the inner error; the category, endpoint, status, and redacted body are the diagnostic surface |

Error categories are stable. Error message text is not (see the stability
policy).

### Response structs are `#[non_exhaustive]`

- Every public response struct in `libfmp::responses` is `#[non_exhaustive]`
  (#342).
- Adding a field the provider started sending is then a minor change, not a
  major one.
- Cost accepted: callers outside the crate cannot build response structs with
  a struct literal or destructure them exhaustively. Tests that need rows
  deserialize JSON.

### Large quantities are `f64` with an integral serializer

| Type | Before | After | Issue |
| --- | --- | --- | --- |
| `StatementAmount` | `i64` | `f64` | #341 |
| `MarketCapitalization` | `u64` | `f64` | #339 |
| share quantities and money fields on `Count` / `u64` | `u64` | `f64` | #340 |
| `Volume` | `f64` (since #337) | unchanged, stays a type alias | #337 |

- The provider sends fractional values and values past the integer range for
  these fields, so an integer type rejected real rows.
- The integral serializer writes an `f64` holding a whole number as a JSON
  integer (`1000`, not `1000.0`), so re-encoded rows keep the wire spelling.
- `Volume` stays `pub type Volume = f64`, not a newtype: callers do arithmetic
  on it directly.

### `NumericString` stays exact text in every SDK

| SDK | Type |
| --- | --- |
| Rust | `NumericString` (validated text) |
| Python | `str` |
| Go | `string` |

- No SDK parses these fields into a float: that would lose digits and change
  the spelling the provider sent.
- Callers that need arithmetic convert explicitly, for example
  `Decimal(row.field)` in Python.

### Python models: value equality, unhashable, keyword-only constructors

- Generated models compare by value (`==` compares every field) (#345).
- They are unhashable (`hash(row)` raises `TypeError`), matching Python's
  rule for a class that defines `__eq__` without `__hash__`. Some models hold
  lists and dynamic JSON, so one rule for every model is simpler than a hash
  on some. Models cannot be `set` members or `dict` keys.
- Constructors are keyword-only, so adding or reordering fields cannot
  silently shift positional arguments.

### `import fmp` is kept

- The distribution is `fmp-py-sdk` and the import package stays `fmp`
  (ADR 0001).
- An unrelated project publishes a PyPI distribution named `fmp`. Installing
  both in one environment makes `import fmp` ambiguous.
- Kept anyway: `fmp` is the name the provider's users expect, and renaming
  the import now would break every caller for a conflict few will hit. The
  package README tells users not to install both distributions in one
  environment.

### Go module path stays `sdk/go`

- The module path stays `github.com/bitbrew-dev/libfmp/sdk/go` with package
  `fmp` (ADR 0030). Tags already exist, so moving it would orphan every
  published version.

### Naming policy

Recorded separately in ADR 0032 because it spans method names, row types, and
Go casing.

## Alternatives considered

- **A source chain on `Error` behind a redacting wrapper.** Rejected: every
  future dependency upgrade could add a URL to its `Display` text, and one
  missed path leaks a credential.
- **Keep integer types and fail decode on fractional rows.** Rejected: the
  rows are real provider data, and failing a whole response over one field
  is worse than a wider type.
- **A `Volume` newtype.** Rejected: no invariant to protect, and a newtype
  forces `.0` or conversions on every calculation.
- **Rename the import package to avoid the PyPI clash.** Rejected as above.

## Consequences

- Widening a response field (`i64` to `f64`, `T` to `Option<T>`) to match
  observed data ships as a minor with a changelog notice, not a major.
- Callers pattern-matching or building response structs must move to field
  access and deserialization.
